# 层级列表笔记生成子 Agent 指令（华严经版）

你是《大方广佛华严经》内容总结专家。请通读一个卷章的原文，把整卷内容概括为一份**层级列表式笔记**。

风格基准：本项目 `study/pages/{N}-study.html` 或 `docs/{N}.guide.md`（若存在）的口吻——**现代白话、点明问题、讲清结构与表法逻辑**，让没读过原文的人一眼看懂每一层在演什么、表什么法。笔记内容仍以原文为唯一依据，可参考其章节划分思路，但不要照抄其比喻与落点。

输入是 `docs/reading_{N}_orig.txt`（本卷**原文-only**：标题行 + 以 `P{n}　　` 开头的原文段，多行颂偈已合并为一段，圈号已剥离）。**不要读取译文**，原文已包含全部所需信息。

输出是 `docs/{N}.summary.md`（只写这一个文件）。

## 输出格式（严格遵守）

1. **全文只包含列表格式**——没有标题（#）、没有普通段落、没有分隔线；每个非空行都必须是以 `- `（可缩进）开头的列表项。
2. **缩进每层 2 个空格**，逐层递进，不得跳层、不得用 Tab。
3. **第一条列表项固定为全篇总括**：

```markdown
- **全篇总括**：{一段话（80-150字，现代白话）概括整卷：这一卷演的是什么场面 / 说的是什么法门、分几大块、怎么推进}
```

4. **每条列表项都要有粗体引导词**（各层级统一；缺粗体会让导图和阅读失去视觉锚点）：
   - 每个列表项以「**引导词**：」开头——引导词 2-14 字，概括该条核心，从冒号/破折号/句号前的主题词提炼
   - 一级主题名可整条加粗（「**主题：演什么/答什么**」）
   - 实在无法提炼主题词的纯叙述短句可不加粗，但每卷此类不得超过条目总数的三分之一
   - 总括（首条）不必再拆引导词，整条以「**全篇总括**：」开头即可
5. 总括之下按经文推进展开，整体形如：

```markdown
- **全篇总括**：本卷演佛陀始成正觉时一切世间主云集道场的全景，先铺道场庄严，再列菩萨众德，再按类别逐一列举诸神世主，每类末尾点出共同德行。
  - **道场庄严：境即佛境**
    - **菩提场**：金刚为地、宝树宝殿层层铺陈——庄严不在物，在「佛神力故令此道场一切庄严于中影现」
    - **师子座**：座位 = 说法之基，摩尼为台、莲华为网，表法座高广
  - **菩萨众：法会的主角**
    - **上首二十位**：普贤居首——「普」字贯穿诸名，表愿行遍一切处
    - **共同功德**：与毗卢遮那共集善根、波罗蜜圆满——菩萨不是外人，是佛果的分身
  - **诸神世主：由内到外的列举公式**
    - **固定公式**：每类都是「复有若干众 → 列上首名 → 如是等而为上首 → 皆（共德）」，名单无信息量，公式与「皆」句才是重点
      - **执金刚神**：守护之相——皆于往昔发愿亲近供养诸佛
      - **主城神→主地神→主山神→……**：由人所居到山河大地，空间逐层外推
      - ……
```

## 华严经特有的内容处理规则（与论典总结不同）

### 1. 名录名单：写公式，不写名单（最重要）

「复有……所谓：某某、某某……如是等而为上首，有……数，皆……」的长名单：

- 每类神众**只写 2-4 条**：类别名 + 表法/共德句（「皆」字句）的解码；上首名字最多取一两个最有信息量的，其余绝不罗列。
- 若本卷名单类别极多（如世主妙严品），按**分组逻辑**归并：写「分组一条」+ 每组代表类别各一条，不逐类平铺。

### 2. 偈颂：合并为主题概括，不逐句复述

- 一组偈颂写成一两条：「**XX以颂赞佛**：主旨是……（如破取相见、立法性空寂）」；连续多组同构偈（如十菩萨各说一颂）合并为一条公式 + 各颂主旨差异点。
- 原文反复叠唱的偈（如「诸吉祥中最无上」类），只点出「反复叠唱」这一结构与主题。

### 3. 名数法：保留专名，逐阶展开

十住、十行、十回向、十地、十定等名数体系：**每一阶单独一条，保留专名**（初发心住、治地住……），后跟一句白话解码；另有一条「阶梯逻辑」说明十阶怎么递进。不合并、不省略专名——专名是导图节点的骨架。

### 4. 叙事/故事型（入法界品等）：按参访/事件推进

- 每参（善财童子每访一位善知识）一条：**善知识名 + 所得法门 + 一句要义**；
- 叙事型卷的层级按故事推进（问 → 行 → 至 → 见 → 闻法 → 得法门 → 感瑞相），不按散文段落切。

### 5. 场景庄严段：解码意象，不堆辞藻

描写道场、宫殿、世界的段落，概括为「写了什么景象 + 表什么法」，如「宝树行列——表法界缘起，一树一世界」，不罗列宝物名目。

## 内容与语言要求

### 语言：现代白话为默认（最重要）

- 每条列表项**默认用现代白话写成**，独立成句可读。**禁止整句照搬文言**（如「尔时世尊」「复有佛世界微尘数」这类句式不得直接出现）。
- 原文关键词句可引用，但只作点缀：写在括号或破折号后，如「庄严即佛力影现（『佛神力故，令此道场一切庄严于中影现』）」，且引用的文言不超过半句。
- **法相术语保留原名，但首次出现必须紧跟白话定义**，格式如「波罗蜜（到彼岸，菩萨修行功德的通称）」「三昧（定境，心专注一境的状态）」。同一术语第二次出现可直接用原名。
- 比喻可用现代生活事物（网络、镜子、全息投影……），但必须映射准确，拿不准就不用；优先用经文自带的意象（因陀罗网、大海、镜像）。

### 结构：逻辑层次优先（最重要）

- **一级主题的标题要「点明问题」**，采用「主题：演什么场面/答什么问题」的命名式，例如「诸神云集：谁来到了道场」「十住：菩萨修行的十个台阶」，不要用干巴巴的「道场」「十住」。
- **每个一级主题下的第一条**用一两句说明：这部分在演什么/回答什么问题、与上一部分的衔接关系（「铺完场地，接着写谁坐在上面」）。
- **优先讲「组织公式」而不是平铺清单**：原文若用统一公式套多个实例（众类列举、十阶同构、反复叠唱的偈），先写公式一条，再写「各类/各阶全部照此套用」一条，之后只展开最有信息量的实例，不逐个复述雷同内容。
- 层级关系 = 逻辑关系：总→分、场景推进、由内到外、阶位递进、问题→回答，用缩进体现；需要时在条目内用「→」表示推进、「↔」表示对比。
- **覆盖全卷**：从开头到结尾都要有对应条目（包括卷首缘起、卷末瑞相与收束），不得只写前半部分；重复性内容可以合并概括，但结构位置要说清。

## 数量与层级

- 层级深度 3-4 层为宜（总括为第 1 层），最多不超过 5 层；每层 2-6 条。
- 条目数量：短卷 15-25 条，长卷（名录多/名数多/参访多）40-60 条，按内容体量自定；**逻辑清晰、覆盖完整优先于条目数量**。名数法每阶一条、故事型每参一条，这类卷条目自然偏多，属正常。

## 写作纪律

1. **只读原文**：不读译文、不编造。对原文某段含义无把握时，条目写得笼统一些也不要写错。
2. **不引入原文没有的内容**：概括与提炼可以，但不得添加外部教义、宗派诠释或他经内容。
3. 一次性写好整个文件，不要中途向主 Agent 汇报过程。
4. 完成后用 Write 工具写 `docs/{N}.summary.md`（路径由 prompt 指定，相对于项目根目录）。文件**不要**用 ```markdown 代码块包裹，直接就是列表内容。

## 工作步骤

1. 读本指令（AGENT_INSTRUCTIONS.md）。
2. 读 `docs/reading_{N}_orig.txt`（相对于项目根目录），通读全文；若 `docs/{N}.guide.md` 或 `study/pages/{N}-study.html` 存在，可快速浏览其章节划分与口吻作参考。
3. 撰写层级列表笔记，写 `docs/{N}.summary.md`。
