# study-huayan 交互学习网页 · 内容撰写规范

你的任务：为《大方广佛华严经》某一卷生成一个**单文件、零依赖的交互式教学网页**，输出到 `study/pages/{N}-study.html`。读者是没有佛学基础、被文言吓退的成年人，目标是让他**不读原文也能弄懂这一卷在说什么、妙在哪里**。

## 华严经与论典的根本不同（先读懂这个再动笔）

《华严经》是**经**不是**论**：它不论证、不定义、不分类推理，而是**用场景、意象、名单、偈颂和巨大的数字来表法**。因此本 skill 的写法与论典型学习页完全不同：

1. **意象即法义**——道场庄严、师子座放光、毛孔容世界、因陀罗网，这些不是文学修饰，而是义理本身。你的核心工作是**解码意象**：这段描写在写什么景象 → 这个景象在表什么法。
2. **名单不是废话**——「复有……神众」的长名单用固定公式推进，名单背后的**结构**（由内到外、由圣到凡、每一类的「皆……」共德句）才是要读的东西。**绝不逐个罗列名字**，讲公式、讲分组、讲代表。
3. **偈颂是表义主角**——华严几乎每卷都有大量偈颂，常承担「点题、破相、显理」的关键角色，必须单独导读，不能一笔带过。
4. **「十」是组织基因**——十住、十行、十回向、十地、十定、十通……遇名数法先讲「为什么是十个、怎么排成阶梯」，再逐阶展开。
5. **卷与卷靠「九会七处」相连**——每卷都属于某一次法会、某一个或几个品，开场必须交代位置与上下卷衔接。

## 输入与输出

- 输入：`docs/{N}.md`（原文 + 白话译文对照，原文含圈号标注 ① ②）。**全文通读后再动笔。**可参考 `docs/{N}.guide.md`（结构导读）与 `docs/{N}.notes.md`（词语注释）辅助理解，但法义以本卷原文与译文为准。
- 骨架模板：`.claude/skills/study-huayan/template.html`——CSS、固定 JS（进度条 / initStepper / initSorter）、HTML 外壳**原样复制，一字不改**，只替换占位符与 `{{SECTIONS}}`、`{{CUSTOM_JS}}`。
- 输出：`study/pages/{N}-study.html`，一个完整自包含 HTML 文件。

## 占位符填写

| 占位符 | 内容 |
|---|---|
| `{{PAGE_TITLE}}` | 《大方广佛华严经》卷N · 交互式学习模块 |
| `{{KICKER}}` | 「大方广佛华严经 · 第X会 · 某某品」（据本卷品题与全经结构填写） |
| `{{HERO_TITLE}}` | 卷第N · 交互式学习模块 |
| `{{HERO_SUB}}` | 用 1-2 句话概括这一卷的本质（例：「这一卷是佛陀始成正觉时，一切世间主云集道场的全景画卷……」） |
| `{{HERO_TAGLINE}}` | 「X 个主题 · Y 个学习步骤 · Z 个落点」（X=章节数，Z 为全页落点块总数，必须 ≥8） |
| `{{NAV_LINKS}}` | `<a href="#s1">① 主题名</a> …` 一行一个主题，按章节数生成 |
| `{{PATH_STEPS}}` | 4-6 个 step-item（见下） |
| `{{CHAPTER_NUM}}` | N（数字），用作 localStorage key |
| `{{SECTIONS}}` | 全部章节 HTML（见内容规范） |
| `{{FOOTER_NOTE}}` | 基于《大方广佛华严经》卷第N（docs/{N}.md 原文译文对照版）制作 · 交互式学习模块<br>意象解读仅助理解，法义以经文为准 |
| `{{CUSTOM_JS}}` | 本章定制交互 JS（stepper 数据、sorter 数据等） |

### PATH_STEPS 格式（data-target 指向导航锚点）

```html
<div class="step-item" data-target="#s1"><label><input type="checkbox" data-step="1"><span class="no">1</span><span class="txt"><b>步骤标题</b><span>一句话说明这一步做什么、对应哪个章节</span></span></label></div>
```

- 4-6 步，由浅入深；第一步通常是「定位本卷」（看懂它在全经的位置），最后一步通常是「偈颂 / 收官」。
- 每个 step 的 data-target 指向对应 section 的 id。

## 章节内容规范（{{SECTIONS}}）

### 总体结构

按该卷实际内容划分 **4-8 个主题章节**，每章：

```html
<section class="chapter" id="sK">
  <div class="sec-head"><span class="num">0K</span><h2>主题名</h2></div>
  <p class="sec-lead">引导段：这一部分在演什么场面 / 回答什么问题，为什么重要。</p>
  <div class="card">…</div>
  …
  <div class="divider"></div>
</section>
```

**每卷必有**：开头的「开场定位」章节（本卷属第几会、哪个品、与前后卷怎么衔接，内含 `.hui-map` 九会定位条）+ 结尾的「收官」章节（偈颂导读 + 全卷回顾）。

### hui-map 九会定位条（开场章节必备）

```html
<div class="hui-map">
  <h3>本卷在全经的位置</h3>
  <div class="hui-chips">
    <span class="hui">第一会 菩提场</span><span class="hui cur">第二会 普光明殿</span>…
  </div>
  <p class="hui-note">一句话：本卷属于第X会·某某品，上一卷说了…，这一卷接着说…。</p>
</div>
```

八个 chip（本卷所在会加 `cur`，相邻会可加 `near`）；hui-note 点明前后衔接。

### 卡片内部的三件套（每张核心概念卡必须有）

1. **quote**（原文引用）：从 `docs/{N}.md` 原文中**逐字摘取**关键文言 1-2 句（可含圈号），附 `<span class="src">—— 卷N原文</span>`。**引文必须是原文精确子串**（校验脚本会逐条核对）。
2. **decode**（解码）：绿色块，两句话：① 这段字面在写什么；② 它在表什么法 / 为什么这样写。意象要解码到「所以呢」那一层。
3. **touch**（落点）：金色块，把这个法义落到今天读者能抓住的东西上。**华严自带大量比喻（因陀罗网、大海、镜像、梦幻），优先用经文自带的意象做落点**；确有把握时才配一个现代场景（如「同一句消息同时出现在千万台手机上」），且对应关系要点明，不牵强。拿不准的义理直接用译文释义，不硬造落点。

```html
<div class="card">
  <h3>标题</h3>
  <div class="quote">文言引文<span class="src">—— 卷N原文</span></div>
  <div class="decode">解码两句话。</div>
  <div class="touch">落点。</div>
</div>
```

### 落点块（.touch）的数量要求

全页 **≥8 个**，每章 **≥1 个**。落点可以是：现代生活场景的对应、读到某段时该问自己的问题、该段与读者修心/处世的关联。**名录型卷不硬编现代故事**——落点可以是「读名单的心法」（如：读到「主城神」时，想想你生活中守护着什么边界）。

### 名录段的处理（华严最大的坑）

遇到「复有……所谓：某某神、某某神……如是等而为上首，有……数，皆……」：

- **绝不逐名翻译罗列**（名单放 `details.dict` 折叠区，注明「可跳过」）；
- 正文章节只讲：① 这个固定公式的结构（类别 → 上首名单 → 数量 → 「皆」共德句）；② 每类神**表什么法**（主城神→守护、主海神→深广、主夜神→幽暗中的光明……）；③ 分组的推进逻辑（由内到外、由圣到凡、地居到空居……）；
- 用 fn-card 翻转卡做「众类表法」卡组（正面=神众类别，背面=表法+代表上首名字一两个+共德句解码）。

### 交互组件（每章 ≥1 个，全页 ≥4 个，类型至少 3 种）

| 组件 | 适用内容 | 用法 |
|---|---|---|
| **fn-card 翻转卡** | 众类表法、意象解码、成组概念 | grid 里放 4-8 张卡，正面 `cn`=名称、`sub`=一句话，背面=解码+`em` 引文或落点 |
| **initStepper 流程推演** | 场景漫游（道场→菩提树→宫殿→师子座）、名数十阶（十住/十地逐一走）、说法缘起链 | 每步 `{t:'标题', d:'<b>名目（白话）：</b>解码'}`；在 `{{CUSTOM_JS}}` 中调用 |
| **initSorter 归类练习** | 偈义归类（这偈在赞什么/破什么）、名数归属判断、众类分属 | `items:[{a:'场景或偈句大意', opts:['A','B','C'], ans:'B', exp:'原因'}]`，5 条左右 |
| **timeline** | 五十三参、九会次第、位次递进、一卷内的叙事推进 | 3-6 个节点，t=名称，d=解码 |
| **yuan-grid 对比卡** | 并列的多类事物（三聚戒、三身、各类世主对比） | 3-5 张卡，y-tag=类别标签 |
| **dict 折叠字典** | 名单、枚举、可跳过的清单 | summary 注明「可跳过」，body 保留条目但按类分组，条目后可附一句白话 |
| **gatha 偈颂** | 卷中关键偈、卷末总摄颂 | lines=颂文（保留原文空格对齐），who=谁在什么场合说，mean=逐联白话+点明这组偈的整体作用；一卷可放多个 gatha |
| **table.nine 对照表** | 名相 ↔ 表法 ↔ 通俗理解 | 表头三列：名相 / 经文中出现处 / 表什么法 |

（华严没有词源段与条件模拟场景，不使用这两类组件。）

### 内容忠实性规则

- **所有法义以 `docs/{N}.md` 为准**；义理解释参考该卷白话译文与 guide.md，不得引入本卷没有的教义，不做宗派比较、不引他经他论。
- 文言引文必须是原文精确子串（含圈号亦可），每章 1-3 条，宁少勿错——校验脚本逐条核对子串。
- 术语首次出现给出白话定义；圈号 ①② 直接显示无妨（表示原文有注释，见 docs/{N}.notes.md），不必解释。
- 意象解读以经文自证为限（同卷或前后文有明说的才引用），超出本卷的「华严宗」诠释不用。

### 章节划分建议（按卷型套用）

- **场景名录型**（世主妙严品、庄严类）：开场定位 → 全卷地图（公式讲法）→ 佛与上首菩萨（重点解码）→ 众类分组表法（fn-card + dict）→ 偈颂与收官。
- **名数法义型**（十住/十行/十回向/十地等）：开场定位 → 说法缘起（升会、入定、加持）→ 名数总纲（为什么是十、阶梯怎么排）→ 逐阶/分组拆解（stepper + 重点阶详讲）→ 关键偈颂 → 收官。
- **世界境界型**（世界成就、华藏世界等）：开场定位 → 结构漫游（stepper 按空间层级）→ 意象解码（fn-card）→ 数字与「重重无尽」 → 收官。
- **故事型**（入法界品）：开场定位 → 参访/叙事地图（timeline）→ 关键参访拆解（每参一个 fn-card 或 card）→ 每参得什么法门 → 收官。

## CUSTOM_JS 要求

- stepper 数据、sorter 数据全部写在 `/* @@CUSTOM_JS@@ */` 位置。
- 模板里 `renderPath();` 必须保留在最后；定制初始化写在它之前。
- 定制 JS 中避免与模板保留名冲突：`loadProgress/saveProgress/renderPath/initStepper/initSorter`。

## 质量自检（写完后逐项过一遍）

1. 无 `{{` 残留占位符。
2. 开场章有 `.hui-map`，八个会 chip 齐全、本卷会高亮。
3. 导航每个锚点都有对应 `id="sK"`；PATH_STEPS 的 data-target 正确。
4. 落点块 ≥8，每章 ≥1。
5. 交互组件 ≥4 个、类型 ≥3 种，且都在 CUSTOM_JS 中初始化。
6. 每张核心概念卡有 quote + decode + touch 三件套；引文为原文精确子串。
7. 名录段没有逐名罗列；名单进了 dict 折叠区。
8. 偈颂有 gatha 导读（逐联白话+整体作用）。
9. 用浏览器打开不报 JS 错误（自行检查括号配对、id 拼写）。
