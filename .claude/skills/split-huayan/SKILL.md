# 划分配对段落（华严经 原文 + 译文对照）

## 用途

把 `docs/{N}.md` 中过长的 原文/译文 配对段切成更短的配对块，方便对照阅读。结果**覆盖写回** `docs/{N}.md`，原文件备份到 `.splitwork/{N}.orig.md`。

**核心设计**：
- **脚本**做确定性工作：解析配对、偈颂识别、按标点切句、splits.json 校验（拼接一致、块数对齐、长度硬上限）、文件重组、字符流校验
- **LLM** 只做语义决策：原文在哪里分（选句子分组）、译文对应怎么分（直接写出译文块）——**不需要数字符**
- **三步流程**：`prepare` → LLM 写 `splits.json` → `apply`

**不变式（脚本强制校验）**：
1. 原文块拼接 == 原原文段（字符级，去空白后比较）
2. 译文块拼接 == 原译文段（同上）——一个字都不能丢、不能改
3. 原文块数 == 译文块数，一一交错排列
4. 偈颂（多行段落 / 含行内全角空格的段落）**永不内部分割**，无论多长

## docs/ 格式约定（多种混用，脚本已统一处理）

与 check-huayan 的识别规则一致，LLM 不需关心格式差异：

- 译文段：以 `*` 开头（部分卷带 `　　` 前缀，如 `　　*译文*`），整块包裹或跨行续行
- 原文段：可能以 `　　`（全角空格）开头，也可能顶格
- 原文与译文间可能有空行，也可能紧接
- 多行颂偈：连续原文行视为同一段原文（偈颂），脚本自动识别、不参与切分
- 页脚杂行（`大方广佛华严经卷第…`、`大正新修大藏经…`、孤立的 `.`/`。`）：自动跳过（重组时会被剔除）
- **重组保留原格式**：未切分的条目（标题、solo、未达阈值的配对、偈颂）按原始行**原样保留**，偈颂的逐行 `*...*` 译文结构不变；只有被切分的配对用规整格式输出（原文块 / `*译文块*`，块间空行）

## 调用方式

```
/split-huayan <start> <end>
```

例如 `/split-huayan 1 5` 处理 `docs/1.md` ~ `docs/5.md`。

## 三步流程

### 第 1 步：prepare（脚本）

```bash
python3 .claude/skills/split-huayan/split_paired.py prepare <s> <e>
```

生成 `.splitwork/{N}.pairs.txt`（待切分长配对列表）和 `.splitwork/{N}.orig.md`（原文件备份）。

阈值默认：原文段 >200 字进入待切分列表（`--max-len` 可调）。

### 第 2 步：LLM 写 splits.json（语义切分决策）

对每个 `{N}.pairs.txt`：

1. **Read** 该文件（一次读完）
2. 对每个 `== P3 (原文291字, 译文397字) ==` 配对，内心完成：
   - **原文分组**：在语义边界处把句子分成若干组，每组是一个完整的意思单元
   - **译文对应**：把译文全文切成**同样数量**的块，块 i 的内容覆盖原文块 i 的意思；译文在自然句号处（。！？”……）切开，不增删改任何字
3. **Write** `.splitwork/{N}.splits.json`，格式：

```json
{
  "P3": [
    {"o": ["P3S1-P3S2"], "t": "译文第一块……"},
    {"o": ["P3S3"], "t": "译文第二块……"}
  ]
}
```

- `o`：句子编号，单个（`P3S2`）或区间（`P3S1-P3S5`），按文档顺序
- `t`：译文块**原文照抄**（从 pairs.txt 的"译文全文"里复制切分），不要改写、翻译或润色
- pairs.txt 里的**所有** P 编号都必须出现在 splits.json 中，一个不能漏

#### 语义边界提示（华严经体裁）

| 边界类型 | 识别特征 |
|---------|---------|
| 新列举项 | "复有……神/菩萨"、"所谓：" 开头的各类神众列举 |
| 称呼开启新段 | "佛子！"、"善男子"、"尔时" 常开始新的开示层次 |
| 问答 | "问……" / "答……" 可分开 |
| 引语引入 | "……白佛言："、"说偈言：" 后接偈颂或引文，此处不切（偈颂是独立段落） |
| 转折/因果 | "然"、"是故"、"何以故" 常开始新层次 |
| 小结 | "是名菩萨摩诃萨第X行/住……" 常单独收尾 |
| 名号清单 | 菩萨/神众名号罗列段，可在 "如是等而为上首" 前后切开 |

#### 切分原则

- **以原文语义为准**：只看原文的语义边界；译文长度不作为切分依据（译文允许比上限长）
- 原文目标 100~250 字/块，硬上限 300 字（apply 会校验，超了会报错让你改）
- 华严经长段可达数千字，组数不限于 2~4，按语义自然分即可
- 引号内的对话尽量保持完整，不要从引语中间切开
- 分号（；）是合法切分边界：华严经常用分号连接并列长句，pairs.txt 的句子即按 。？！；切出
- 名号清单（佛、菩萨、诸神名号）可在清单的自然停顿处切，不必强求整段一块

#### 防输出过长纪律

**绝对不要在对话中输出分析过程、配对解读、splits 内容复述。**

- ❌ 不输出"P3 分析：……分 3 组……"
- ❌ 不复述译文块内容
- ✅ 只输出极简状态（如"1.md splits.json 已写入，8 对"）

正确做法：内心分析后直接 Write splits.json，前后只输出一行状态。

### 第 3 步：apply（脚本）

```bash
python3 .claude/skills/split-huayan/split_paired.py apply <s> <e>
```

- 校验 splits.json（编号合法、块数对齐、两侧拼接与原文完全一致、原文块 ≤300 字）
- 重组文件并覆盖 `docs/{N}.md`（同时统一格式：去缩进前缀、块间空行）
- 端到端校验：把重组后的文件重新解析，逐项核对每个原始配对的原文块拼接、译文块拼接及结构条目，全部一致才写回

**全部 ✓ 即完成**。有 ✗ 时按报错修正 splits.json 再重新 apply。注意：apply 成功后该文件已是重组结果，**不要对该文件重复 apply**（重跑会因找不到长配对而报错，属预期保护，不会损坏文件）。

## 操作清单

### 小范围（≤5 卷）：主代理直接处理

1. `prepare <s> <e>`
2. 对每卷：Read `{N}.pairs.txt` → Write `{N}.splits.json` → 输出一行状态
3. `apply <s> <e>`

### 大范围（≥6 卷）：分批处理

每批 5 卷左右，重复上述三步。pairs.txt 很紧凑，主代理逐卷 Read + Write 即可，无需子代理。

## 失败处理

| 报错 | 原因与修法 |
|------|-----------|
| `编号格式错误` / `句号越界` | splits.json 里 o 编号写错，对照 pairs.txt 修正 |
| `数量不一致` | 原文组数 ≠ 译文块数，补齐 |
| `原文块拼接…不一致` / `译文块拼接…不一致` | t 抄写时漏字/多字/改字，重新从 pairs.txt 复制 |
| `超过硬上限 300 字` | 该组句数太多，再分一组（译文也跟着多切一块） |
| `长配对未出现在 splits.json 中` | 漏了对，补上 |
| `字符流校验失败` | 极少见：检查 docs/{N}.md 是否被手工改动过，必要时从 `.splitwork/{N}.orig.md` 恢复后重跑 |

## 重要注意事项

1. **偈颂永不分割**：脚本已自动排除（多行段落/含行内全角空格），splits.json 中也不该出现偈颂配对。
2. **不修改任何文字**：splits.json 只决定"在哪里分"，t 必须原文照抄。
3. **原文件可恢复**：`.splitwork/{N}.orig.md` 是 prepare 时的原文件备份。
4. **中间文件**：`.splitwork/` 下的 pairs.txt / splits.json / orig.md 完成后可保留复查，也可删除。
5. **格式兼容**：未切分部分原样保留，被切分的配对输出为规整的 原文块/`*译文块*` 格式，与 check-huayan / fix-huayan 的解析规则兼容（已用真实卷验证原文流/译文流守恒）。
6. **不要用 awk 数长度**：多字节 locale 下 awk 按字节计，中文会误报；长度校验由 apply 完成。
