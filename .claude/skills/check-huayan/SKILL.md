# 角色与目标

你是《大方广佛华严经》译文校对 Agent。任务是校对 `docs/` 目录下（如 `docs/1.md` ~ `docs/80.md`）的译文质量，产出报告到 `docs/{N}.check.md`。

**核心关注点**：检测「近似未翻译」——译文仅对原文做标点替换、个别字词替换、语序微调，整体仍是古文句式，没有真正转换为现代白话。这是批量翻译最常见的退化现象，必须检出。

# 架构设计

```
prepare_check.py  →  docs/pairs_{N}.json + docs/check_{N}_batch*.json  →  [LLM 逐段校对]  →  docs/issues_{N}_batch*.json  →  build_report.py  →  docs/{N}.check.md
```

- `prepare_check.py`：机械提取「原文段→译文段」对，按批切块（含前 2 段上下文）。**不做任何质量判断**。
- LLM：读取每批的**全量原文+译文**，逐段判断质量问题，写 issues JSON。**判断全部由 LLM 完成**——因为校对需要看全量信息才能判断"近似未翻译"这种语义性问题，不依赖脚本相似度算法。
- `build_report.py`：合并各批 issues → 生成 `docs/{N}.check.md`。

# docs/ 格式说明（重要）

华严经 `docs/{N}.md` 格式**有多种混用**，脚本已统一处理：

- 译文段：以 `*` 开头（部分卷译文前带 `　　` 前缀，如 `　　*译文*`，均识别）
- 原文段：可能以 `　　`（双全角空格）开头，也可能无前缀直接顶格
- 段间分隔：部分卷原文与译文间有空行，部分卷译文紧接原文无空行
- 多行颂偈：连续非 `*`、非 `#`、非空行视为同一段原文
- 译文块跨行：极少数译文有硬换行续行（前一行以 `*` 开头但未以 `*` 结尾，续行无 `*` 前缀），脚本会并入同一译文块
- 部分卷末尾有页脚杂行（`大方广佛华严经卷第…`、`大正新修大藏经…`、孤立的 `.`），脚本自动跳过，不算段落

统一识别规则：**以 `*`（或 `　　*`）开头的行是译文，以 `#` 开头的是标题，空行是分隔，其余行都是原文**。LLM 不需关心格式差异，只读批次 JSON 中已规整的 orig/trans 字段。

# 校对维度

逐段检查，命中任一即记录问题：

| 代号 | 类型 | 说明 |
|------|------|------|
| MISSING | 译文缺失 | 原文段后无译文 |
| NEAR-COPY | 近似未翻译 ★重点 | 译文仅做标点/个别词替换，仍是古文句式，未真正白话化 |
| VERSE-NOT-TRANSLATED | 颂偈未译 | 颂偈照抄原文，未译为有韵律白话 |
| FORMAT | 格式问题 | 译文块整体未以 `*` 开头且以 `*` 结尾、含"译文"前缀、标题被翻译（颂偈跨行 `*...*` 与逐行 `*...*` 均合法，不算格式问题） |
| ERROR | 翻译错误 | 误译、漏译、乱码/外文字符混入（如"庄iam"）、术语错误 |
| OTHER | 其它质量 | 语句不通、失真、前后矛盾、简体译文中残留繁体字（如"菩薩""威儀"） |

**关键判别**（NEAR-COPY）：
- 把译文与原文逐句对比，若去掉标点和个别替换词后，**超过八成句子是原词原句** → 近似未翻译。
- 保留文言虚词（尔时、悉、咸、皆、而、故、令、为欲、所谓、如是、若诸、已、尝、靡不）与古文语序 → 近似未翻译。
- 合格译文的特征：确实换用了白话表达（如"于阗国三藏实叉难陀奉 制译" → "于阗国三藏法师实叉难陀奉皇帝命令翻译"），即便个别术语保留原样。

**绝不硬凑问题**：段落合格就**不记录**。宁缺毋滥。

**名号保留是正常的**：佛、菩萨、诸神、诸天的名号清单（如"普贤菩萨摩诃萨""妙色那罗延执金刚神""宝峰开华主山神"）在译文中逐字保留是本经翻译惯例，**绝不能**仅因名号未译就判为 NEAR-COPY 或 ERROR。判断要看名号之外的叙述部分是否已白话化。

# 自动化执行工作流

## 步骤一：准备（确定性脚本）
对每个目标文件 `N`：
```
python3 .claude/skills/check-huayan/prepare_check.py <N>
```
生成 `docs/pairs_{N}.json` 和 `docs/check_{N}_batch*.json`（每批最多 20 个段对，含前 2 段上下文）。

**批次大小**：20 段/批。校对需逐段对比原文与译文，认知负荷高于生成任务，与 read-huayan 流水线对齐取 20，避免单 Agent 上下文过长导致后半段草率判断。

## 步骤二：并行派发校对子 Agent

**关键**：所有批次必须在同一轮消息中并行派发，确保每个子 Agent 独立校对，互不干扰。对文件内每批派发一个子 Agent（`subagent_type: general-purpose`），prompt 精简（指令在 AGENT_INSTRUCTIONS.md，子 Agent Read 一次命中缓存）：

```
读取 .claude/skills/check-huayan/AGENT_INSTRUCTIONS.md 获取校对指令，按其要求校对。

批次文件：docs/check_{N}_batch{batch_num}.json
输出文件：docs/issues_{N}_batch{batch_num}.json
```

**上下文衰减控制**：单文件段落数很多时，每批 ≤ 20 段、每批独立子 Agent，避免单个 LLM 上下文过长导致后半段校对质量下降。

## 步骤三：合并问题 + 生成报告

所有子 Agent 完成后，运行：
```
python3 .claude/skills/check-huayan/build_report.py <N>
```
读取 `docs/pairs_{N}.json` 和所有 `docs/issues_{N}_batch*.json`，生成 `docs/{N}.check.md`。

**JSON 容错**：issues 文件是 LLM 生成的 JSON，可能因值内含 ASCII 双引号/换行未转义而解析失败。`build_report.py` 自动检测并修复（按段落号键边界切分，正则提取字段）；个别批次无法修复时跳过该批并告警，不影响整体报告生成。若报告缺失某些段号，说明对应批次文件损坏未能修复，需重新派发该校对批次。

报告格式：
```markdown
# docs/{N}.md 译文校对报告

- 段落总数：X
- 问题段落数：Y（占 Z%）
- 校对时间：<日期>

## 问题列表

### 段落 3 【近似未翻译】
- **原文**：……
- **译文**：……
- **问题**：译文仅对原文做标点替换，整体仍是古文句式，未真正转换为白话。
- **修改建议**：改为：……

### 段落 15 【译文缺失】
- **原文**：……
- **译文**：（无）
- **问题**：原文段后没有译文。
- **修改建议**：补译此段。

……（每段一个 ### 小节，按段落号排序）

## 汇总
- 近似未翻译（NEAR-COPY）：n 段
- 译文缺失（MISSING）：n 段
- 颂偈未译（VERSE-NOT-TRANSLATED）：n 段
- 格式问题（FORMAT）：n 段
- 翻译错误（ERROR）：n 段
- 其它（OTHER）：n 段
```

若某文件**完全没有问题**，报告输出：
```markdown
# docs/{N}.md 译文校对报告

- 段落总数：X
- 问题段落数：0

✅ 未发现译文质量问题，本文件无需修改。
```

## 步骤四：清理
删除临时文件：`docs/pairs_{N}.json`、`docs/check_{N}_batch*.json`、`docs/issues_{N}_batch*.json`。

# 大文件处理

- 每文件段落数由 `prepare_check.py` 输出决定批次数量。
- 批次在文件内、以及多个文件之间均可并行派发。
- 单文件批次较多时（>8），分批派发（如每轮 8 个），避免一次性并发过多。

# 交互反馈

- 启动时，简要确认校对的卷范围。
- 派发后保持静默高效。
- 完成后告知每文件的问题统计。
- 结束时输出简明报告：校对文件数、发现的问题段落总数。
