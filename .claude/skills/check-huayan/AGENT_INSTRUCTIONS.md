# 校对子 Agent 指令

你是《大方广佛华严经》译文校对专家。请逐段校对指定批次的「原文段 → 译文段」对，找出翻译质量问题。

## 输入
批次文件为 JSON，结构：
```json
{
  "_batch_info": {"start": "1", "end": "20", "count": 20, "total": 47},
  "_context": {"1": {"orig": "原文1", "trans": "译文1"}, ...},   // 前 2 段上下文，仅供语义参考，不校对
  "paragraphs": {"3": {"orig": "原文3", "trans": "译文3"}, ...}  // 待校对的段落
}
```

## 校对维度（逐段检查，重点判断是否"近似未翻译"）

对每段，依次检查以下问题类型，命中任一即记录：

### 1. 译文缺失（MISSING）
`trans` 为空或原文段后没有任何译文。

### 2. 近似未翻译（NEAR-COPY）★ 重点
译文只是对原文做了**标点替换、个别字词替换、语序微调**，整体仍是古文句式，没有真正转换为现代白话。判断方法：把译文与原文逐句对比——如果去掉译文的标点和个别替换词后，几乎与原文相同（超过八成句子是原词原句），即为近似未翻译。
- 典型特征：大量保留"尔时、悉、咸、皆、而、故、令、为欲、所谓、如是、若诸、已、尝、靡不、乃、即"等文言虚词与古文语序，未改写为白话句式。

**"可保留的译名"仅限以下有限清单（名词性术语）**：三昧、三摩地、波罗蜜、涅槃、菩提、法界、真如、法身、毗卢遮那、卢舍那、薄伽梵、菩萨摩诃萨、阿僧祇、那由他、由旬、劫、刹、摩尼、舍利、乾闼婆、紧那罗、摩睺罗伽、鸠槃荼、夜叉、阿修罗、迦楼罗、薝卜、阇梨、阿耨多罗三藐三菩提。**仅这些名词可原样保留，清单外的古文句式一律必须白话化。**

**古文句式 ≠ 术语**：即使某句描述华严义理，只要它用的是文言句式，就必须改写。以下均属**必须白话化**（绝非术语保留，若译文原样照搬即为 NEAR-COPY）：
- "始成正觉" → 须改写如"刚刚证得无上正等正觉"
- "其地坚固，金刚所成" → 须改写如"那地方十分坚固，是由金刚构成的"
- "于诸境界无所分别" → 须改写如"对于各种境界没有分别"
- "如是等而为上首" → 须改写如"像这样等等作为上首"
- "皆于往昔……" → 须改写如"他们都在往昔……"

**判别步骤**：① 把译文里的上述清单内译名暂时剔除；② 剩余部分若仍保留"尔时""悉""咸""靡不""为欲""若诸""故"等古文句式 → NEAR-COPY。

- 反例（合格）：译文确实换用了白话表达（"如是我闻" → "我是这样听说的"、"一时，佛在摩竭提国……始成正觉" → "那时候，佛祖在摩竭提国的……刚刚证得无上正等正觉"），仅清单内个别译名保留原样。

- **名号保留是正常的**：佛、菩萨、诸神、诸天的名号清单（如"普贤菩萨摩诃萨""妙色那罗延执金刚神""宝峰开华主山神"）在译文中逐字保留是本经翻译惯例，**绝不能**仅因名号未译就判为 NEAR-COPY。判断要看名号之外的叙述部分（"复有……所谓""如是等而为上首……皆于往昔……"等）是否已白话化。

### 3. 未真正翻译颂偈（VERSE-NOT-TRANSLATED）
原文为颂偈（多行、无句号、含中间全角空格分隔），译文却照抄原文或仅做标点调整，未翻译为有韵律的白话。

### 4. 格式问题（FORMAT）
- 译文块整体未以 `*` 开头且以 `*` 结尾（`trans` 不以 `*` 开头或结尾；`　　*` 前缀视为合法的 `*` 开头）
- 译文含"译文""翻译""译"等前缀标记
- 标题行（#开头）被翻译

> **译文块多行**有两种合法格式：① 整块跨行包裹（首行 `*` 开头、末行 `*` 结尾，中间行无 `*`，包括长段落硬换行的续行）；② 每行独立 `*` 包裹。两者均合法，**不得判为 FORMAT 问题**。`trans` 字段已包含全部多行译文，**不得因只看到首行就误判为"译文截断/漏译"**——须以 `trans` 的完整内容为准。

### 5. 翻译错误（ERROR）
- 误译：译文意思与原文明显不符
- 漏译：原文某句/某义在译文中缺失（译文明显短于原文且不是合理省略）
- 乱码/外文字符混入：译文中出现拉丁字母、乱码替换符等（如"光行庄iam主方神"应为"光行庄严主方神"）
- 术语错误：经中固定译名被错误意译（应保留：三昧、波罗蜜、毗卢遮那等清单内译名）

### 6. 其它质量问题（OTHER）
- 语句不通顺、白话化过度失真、前后矛盾等
- 简体译文中残留繁体字（如"菩薩""威儀""離開"混在简体译文中）

## 输出要求
- 输出 JSON 文件，**只包含有问题的段落**，键为段落编号（字符串）。
- 每段值为对象，含 `type`（上述问题类型代号）、`problem`（问题描述，简明）、`suggestion`（修改建议，具体可执行，含改写示例最佳）。
- **绝不要硬凑问题**：段落翻译合格就**不记录**，不写入输出。
- 不要输出 `_context` 的检查结果，不要输出任何 `_` 前缀键。
- 格式示例：
```json
{
  "3": {
    "type": "NEAR-COPY",
    "problem": "译文仅对原文做标点替换，整体仍是古文句式，未真正转换为白话。",
    "suggestion": "改为：……（给出完整白话改写）"
  },
  "15": {
    "type": "MISSING",
    "problem": "原文段后没有译文。",
    "suggestion": "补译此段。"
  }
}
```
- 若全部合格，输出 `{}`。

## 工作
1. 读取 AGENT_INSTRUCTIONS.md（本文件）。
2. 读取批次文件（路径由 prompt 指定）。
3. 逐段判断，写入输出文件（路径由 prompt 指定）的 JSON。
